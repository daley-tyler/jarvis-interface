# Distribution decision

This is the published source-only portfolio repository. The Python code and tests are reviewable and usable without devices. A complete visual application is not included.

I inspected the cleaned development scene rather than returning to an unreviewed original. Its literal project-relative file references and the 55 explicitly enumerated renderer asset paths exist in the private development folder. Native extraction shows an external `toxes/MediaPipe.tox` dependency and an embedded OpenPose component. File existence and a successful native round trip do not establish redistribution rights or a fresh runtime result.

## What is included

| Material | Basis and scope |
| --- | --- |
| Python modules from the existing JARVIS prototype | Retained as project source with its provenance explained; upstream frameworks are not claimed as my work |
| Reliability and privacy maintenance | Documented current changes, prepared with Codex assistance; no invented development history |
| Automated tests | Synthetic values and fake device/operator boundaries; no captured recordings or images |
| README and Mermaid architecture diagram | Written for this project; no copied visual artwork |

No scene, component binary, image, audio, NumPy sprite, font file, model weight, screenshot, backup or third-party asset is included. Dependencies are installed separately. No root source-code license has been assigned.

## Why the complete scene is excluded

The [upstream MediaPipe TouchDesigner repository](https://github.com/torinmb/mediapipe-touchdesigner) declares an [MIT license](https://github.com/torinmb/mediapipe-touchdesigner/blob/main/LICENSE). Its [web entry point](https://github.com/torinmb/mediapipe-touchdesigner/blob/main/index.html) also carries a MediaPipe Authors Apache 2.0 notice. Those are useful attribution evidence, but I have not matched every bundled dependency, model and binary in my local component to a version and its notices. A current repository license alone is not a complete manifest for that binary.

The saved scene also contains `OpenPose/OPEN_POSE_SKELE`, whose embedded About callback credits Dotsimulate. I found no matching redistribution terms in the local release. Existing globe textures, glyph atlases, rings, cinematic backgrounds and other pre-rendered HUD graphics also lack a complete provenance record. I have not inferred permission from their presence in a downloaded folder. Personal portraits and recording-derived ambience were removed during the earlier privacy cleanup; their replacements do not establish rights for the other graphics.

The private scene retains a browser-based camera path separate from its Video Device In TOP. Selecting a cinematic background does not establish that capture is disabled. I did not launch it for a new screenshot. The existing camera-free screenshot is also excluded because its remaining graphics share the provenance gap.

A later full distribution would need a rights manifest for the exact included components/assets, portable path validation from a fresh location, a hardware-disabled startup path, another saved-state privacy audit, and an explicitly approved runtime check. I have not removed arbitrary upstream nodes or substituted an untested replacement scene simply to make the package look complete.
